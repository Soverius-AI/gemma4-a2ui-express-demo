# Training

Retrains the Gemma 4 Express LoRA with [Unsloth](https://unsloth.ai). This
folder is self-contained: copy it to the training machine and run it there.

| File                     | Contents                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------- |
| `train.py`               | The training run                                                                                        |
| `data/train.jsonl`       | 512 conversations: form creations, action answers and edits, informational cards, and multi-turn chains |
| `data/valid.jsonl`       | 78 validation conversations                                                                             |
| `data/test.jsonl`        | 49 held-out chain steps for compile-rate evaluation; `test.meta.json` holds each step's committed views |
| `data/system-prompt.txt` | The system prompt the app sends; it replaces each row's own                                             |

Each row is `{"messages": [system, user, assistant]}`. The first 159 training
rows and 21 validation rows are the rows both published adapters were trained
on; the 81 and 9 rows after them are compiler-checked informational cards
(venues, podcasts, products) with edits, added on 2026-11-07 because the demo's
card prompts had no training coverage. The remaining rows are multi-turn chains
(card → edits → second-view form → submit → edit, and form → filled submit →
edit → second-view card) generated by driving the real agent with scripted
answers, so every user turn is byte-exact with what the app sends, including
the conversation prefix, live views and checkout guidance. `test.jsonl` holds
whole chains the model never trains on. Their system turns hold an older prompt
(earlier SDK catalog wording plus demo guidance and examples), so `train.py`
swaps in `system-prompt.txt`: the A2UI SDK's prompt alone, exactly as the app
sends it. An app test fails if the two ever differ.

## Run

Needs Python 3.12 and an NVIDIA GPU with CUDA (24 GB is a safe size; the
longest row is about 8,500 tokens) or Apple Silicon. On Apple Silicon Unsloth
uses its MLX backend: the base loads with runtime 4-bit quantization, a 120-step
E2B run takes about 14 minutes on an M5 Max, and the adapter is saved in
`mlx_lm` format, which `../model-tools` merges directly.

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python train.py --size e2b      # or --size e4b
```

The base model downloads from Hugging Face at a pinned revision. A run writes
to `runs/<size>/`:

- `checkpoints/checkpoint-N/`: an adapter every 20 steps (E2B) or 40 (E4B),
  with its validation loss in `trainer_state.json`
- `adapter/`: the adapter after the last step
- `run.json`: base model, steps and data hashes

After an interruption, rerun the same command with `--resume`. `--steps`
overrides the step count, and `--output` the run directory.

## Evaluate

`data/test.jsonl` holds whole follow-up chains the model never trains on. To
score an adapter, generate every step with the app's exact request and compile
each answer against the views the chain had committed:

```sh
.venv/bin/python tools/eval_testset.py data/test.jsonl out.json runs/e2b/adapter
cd .. && TESTSET_ROWS=training/data/test.jsonl TESTSET_META=training/data/test.meta.json \
  TESTSET_OUT=training/out.json pnpm exec vitest run src/app/domains/express/data/testing/eval-testset.test.ts
```

`out-compiled.json` lists the pass rate per step kind and every failure. The
rows come from `src/app/domains/express/data/testing/generate-chains.test.ts`,
which drives the real agent (set `CHAINS_OUT` to regenerate); `tools/gen_cards.py`
wrote the single-turn card rows. `tools/eval_testset.py` needs `mlx_lm`, which
the Unsloth install brings on Apple Silicon.

## Recipe

LoRA rank 8, alpha 16, no dropout, on every language-model projection
(vision and audio stay frozen); Adam at a constant 1e-4 without clipping;
batch 1; seed 3407; sequences up to 12,288 tokens; loss on the assistant turn
only. Validation drops one row that also appears in `train.jsonl`.

| Size | Base                     | Steps | Published adapter |
| ---- | ------------------------ | ----- | ----------------- |
| E2B  | `unsloth/gemma-4-E2B-it` | 120   | checkpoint 100    |
| E4B  | `unsloth/gemma-4-E4B-it` | 160   | checkpoint 40     |

The originals were trained with `mlx_lm` on 4-bit weights; this run uses
Unsloth's 4-bit loading, so it reproduces the recipe, not identical weights.
Pick the checkpoint by trying it in the app, not by validation loss alone.

To run a retrained E2B adapter in the app's WebLLM option, merge and convert
it with [`../model-tools`](../model-tools/README.md).
